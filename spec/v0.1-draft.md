# ASCII Wireframes Specification v0.1 (DRAFT)

**Status**: Early Draft
**Last Updated**: 2025-10-26

## Abstract

This document defines ASCII wireframes as a human-readable, plain-text format for communicating user interface designs to AI coding assistants and human developers.

## Goals

- Provide a consistent, unambiguous way to describe UI layouts
- Enable rapid iteration on interface design
- Work seamlessly with version control systems
- Be easy to write without special tools
- Be immediately understandable by both humans and AI

## Core Concepts

### 1. Box Drawing

ASCII wireframes use box-drawing characters to represent visual boundaries and structure:

```
Basic box:
┌─────────┐
│ Content │
└─────────┘

Nested structure:
┌─────────────────────┐
│ Header              │
├─────────────────────┤
│ ┌─────┐  ┌─────┐   │
│ │ Box │  │ Box │   │
│ └─────┘  └─────┘   │
└─────────────────────┘
```

**Box-drawing characters**:
- `┌ ┐ └ ┘` - corners
- `─ │` - horizontal and vertical lines
- `├ ┤ ┬ ┴ ┼` - connections

### 2. Interactive Elements

Common UI components are represented with brackets and symbols:

```
Buttons:    [ Submit ]  [ Cancel ]
Input:      [____________]  or  [ Enter text...    ]
Checkbox:   [ ] Unchecked    [x] Checked
Radio:      ( ) Unselected   (•) Selected
Dropdown:   [ Select...  ▾ ]
Link:       → Learn More  or  Learn More →
Icon:       [🔍] or [≡] or [⚙]
```

### 3. Lists and Grids

Represent collections of items consistently:

```
Simple list:
- Item 1
- Item 2
- Item 3

Card grid:
┌─────────┐  ┌─────────┐  ┌─────────┐
│ Card 1  │  │ Card 2  │  │ Card 3  │
│         │  │         │  │         │
└─────────┘  └─────────┘  └─────────┘
```

### 4. Text Hierarchy

Use spacing and formatting to indicate importance:

```
# Large Heading

## Medium Heading

Regular body text

[Primary Action]  [Secondary Action]
```

### 5. Layout and Spacing

Indentation indicates hierarchy and grouping:

```
┌─────────────────────────────┐
│ App                         │
├─────────────────────────────┤
│                             │
│  Main Content Area          │
│                             │
│  ┌──────────────────────┐   │
│  │ Nested Component     │   │
│  │                      │   │
│  │  Further nested      │   │
│  └──────────────────────┘   │
│                             │
└─────────────────────────────┘
```

## Annotations

Use comments to provide additional context:

```
┌─────────────────────────────────────┐
│ Dashboard                      [≡]  │
├─────────────────────────────────────┤
│                                     │
│  // User profile section            │
│  ┌──────────────────────────────┐   │
│  │ @username             [Edit] │   │
│  └──────────────────────────────┘   │
│                                     │
└─────────────────────────────────────┘
```

## Best Practices

1. **Be Consistent**: Use the same characters for the same elements throughout
2. **Add Context**: Include labels and annotations where helpful
3. **Show State**: Indicate interactive states (selected, disabled, etc.)
4. **Keep it Simple**: Focus on structure over pixel-perfect representation
5. **Consider Responsive**: Note breakpoints or layout variations when relevant
